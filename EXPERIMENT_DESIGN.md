# Постановка экспериментов в Fly-Sim

## Принцип: организм не знает, что он в эксперименте

Экспериментатор управляет только **средой**: яблоко, воздух, температура пола, запахи,
удары, перенос мухи (как пинцетом), травмы. Внутрь мухи эксперимент не вмешивается:
адаптация, обмен веществ, забывание — собственные процессы организма (`Fly.pass_time`,
`MotorReadout.adapt`). Роли разделены:

| Роль | Код |
|---|---|
| Organism | `flysim/agent/fly.py` |
| Environment | `flysim/world/` |
| Protocol | `flysim/sim/protocol.py → PROTOCOLS` |
| Runner | `run_series()` (несколько процессов) |
| Analyzer | `analyze()` |
| Report | `scripts/report.py`, `scripts/series.py stats` |

## Структура протокола

```
Experiment
├── Hypothesis             — что проверяем
├── Organism configuration — пол, коннектом, голод, травмы
├── Environment            — яблоко, воздух, зоны, запахи
├── Stimuli                — что, когда, сколько
├── Groups                 — экспериментальная и контрольные
├── Measurements           — метрики (и три уровня: нейроны → команда → движение)
├── Replications           — число seed, расчёт мощности
├── Results                — средние, 95 % ДИ, размер эффекта, p
└── Interpretation         — уровень вывода (1, 2 или 3)
```

## Обязательные контроли для выводов об обучении

| Группа | Что отключено | Что исключает |
|---|---|---|
| `no_plasticity` | пластичность KC→MBON | поведение без обучения (рефлексы, врождённое) |
| `no_us_shortcut` | A24 (наказание по физиологии) | результат держится на обходе |
| `no_reward_shortcut` | A25 | то же для награды |
| `reflex_only` | всё перечисленное | режим `connectome_only` |

Где они стоят в `PROTOCOLS` (`flysim/sim/protocol.py`):

| Протокол | Контрольная группа | Группы |
|---|---|---|
| `tmaze_choice` (удар током) | `no_plasticity` | experimental, no_plasticity, no_us_shortcut, connectome_only |
| `place_avoidance` (жар 44 °C) | `no_plasticity` | experimental, no_plasticity, no_us_shortcut |
| `food_search` (удар на плоде) | `no_plasticity` | experimental, no_plasticity, no_us_shortcut |
| `conflict` (голод против жара) | `fed` | hungry_24h, fed |

У всех мух есть VNC (с 0.4.0), поэтому **жар** идёт к PPL1 только через коннектом (ноцицепторы
ног → VNC → мозг), и в `place_avoidance` группа `no_us_shortcut` по механизму совпадает с
`experimental` — это проверка, а не новый контроль. Для **удара током** обход A24 — единственный
путь к PPL1 (рецепторов тока в модели нет), поэтому `no_us_shortcut` в `tmaze_choice` и
`food_search` показывает, что остаётся без обхода. `no_reward_shortcut` пока не нужен: ни один
протокол не использует награду как подкрепление.

Правило: **результат, полученный с обходом, никогда не выдаётся за полностью биологически
реконструированный.** Режим пишется в манифест каждого прогона.

## Дизайн протоколов

- **Старт:** положение и курс мухи берутся из seed (случайно в пределах протокола); тест
  начинается из той же позы, что и исходное измерение (`place_avoidance`, `food_search`,
  `tmaze_choice`).
- **T-лабиринт — реципрокный** (Tully & Quinn 1985): какой запах наказан (этилацетат или
  изоамилацетат) и с какой стороны он стоит на тесте, задаётся seed (`seed % 2`, `(seed // 2) % 2`).
  PI половины = доля времени у CS− − доля у CS+; одна единица N = среднее двух реципрокных половин.
- **Место-обучение:** зона пола 44 °C (ноцицепторы ног срабатывают выше ~40 °C, A80; горячая
  пластина в тестах ноцицепции ~40–46 °C, Neely et al. 2010), без запахов, с тремя зрительными
  ориентирами разного размера за стенками арены; исходное окно и окно теста равны.
- **Конфликт:** кольцо пола 42 °C вокруг бродящего яблока (выше порога ноцицепторов, пересекается
  за секунды; гибель от жара требует минут, A94).

## Воспроизводимость

`experiment_id = hash(версия модели, протокол, группа, seed, параметры)`; всё нужное для
повторения — в `manifest.json` (версия git, коннектом, seed, стимулы, параметры, режим,
полнота нервной системы). Каждый вызов `run_series` пишет `run_id` и `model_version` в каждую
запись `results/series_<протокол>.jsonl`; файл дописывается между прогонами, поэтому
`analyze()` по умолчанию берёт **только последний прогон** (`--run all --version <v>` —
объединить прогоны одной версии модели).

## Статистика

- Повторы — независимые seed: у каждой группы **свой поток seed**
  (`group_seed = seed0 + crc32(протокол/группа) mod 10⁵ × 1000 + r`), т. е. группы не делят
  шум, начальную позу и стороны лабиринта; поэтому тесты непарные. Seed контроллера ходьбы
  NeuroMechFly задаётся в `body_nmf.py` (отдельная правка).
- Для каждой группы: среднее, SD, 95 % доверительный интервал (t-распределение).
- У каждого протокола явная **контрольная группа**; каждая другая группа сравнивается с ней:
  разность средних (группа − контроль) с 95 % ДИ Уэлча, Cohen's d (знак = группа − контроль),
  Welch t-тест и Манн–Уитни; p-значения дополнительно с **поправкой Холма** на число сравнений.
- **Мощность:** `scripts/series.py stats` сообщает число повторов на группу для мощности 80 %
  при наблюдаемом эффекте; ориентиры: d=0,8 → 26, d=1,2 → 12, d=2 → 6. В T-лабиринте единица —
  пара реципрокных половин, т. е. прогонов вдвое больше.
- **Бюджет:** `scripts/series.py plan <протокол> <n>` — оценка времени на этой машине;
  на мощном железе: `scripts/series.py run <протокол> <n> --proc <ядра>`.

## Три уровня выводов

1. Система демонстрирует определённую нейронную динамику и поведение.
2. Эта динамика соответствует известным биологическим механизмам (нужна валидация).
3. У системы может быть субъективный опыт — требует отдельных доказательств; модель таких
   утверждений не делает.

## Отслеживание (tracking)

Измеряются: интеграция сенсорики (аддитивность ответов), устойчивость внутренних состояний
(затухание после стимула), сохранение обучения (кривые удержания), восстановление после
воздействия, гибкость поведения при смене условий, схема тела (функция каждой ноги). Индикаторы
метакогниции (задержка решения, колебания) только отслеживаются. Ни одна метрика сама по себе не
является показателем сознания.
